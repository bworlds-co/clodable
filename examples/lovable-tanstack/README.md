# Crumb & Co. (Lovable TanStack Start template)

A fictional bakery site built as a copy of what Lovable generates with its **current template**
(`tanstack_start_ts_current`). Lovable has used this template for new apps since May 13, 2026. It
uses TanStack Start with SSR, React 19, Tailwind CSS 4 and Vite 8, wired through
`@lovable.dev/vite-tanstack-config`. Cloclod's dev tooling is developed and tested against it.

This is a standalone **npm** project with its own `package-lock.json`. It is not part of the pnpm
workspace.

## Run it

```sh
npm install
npm run dev        # vite dev, SSR on http://localhost:8080 (falls back to 8081… if 8080 is busy)
npm run build      # vite build -> .output/ (Nitro, cloudflare-module preset by default)
npm test           # vitest (template routing test)

# Run a production build locally with Node:
NITRO_PRESET=node-server npm run build && PORT=3000 node .output/server/index.mjs
```

`npm run preview` (`vite preview`) does not work locally after the default build. It fails with
`ERR_MODULE_NOT_FOUND …/dist/server/server.js`: Nitro writes a Cloudflare worker to `.output/`, but
TanStack Start's preview server expects `dist/server/server.js`. A real Lovable export behaves the
same way, because `vite.config.ts` and the config package are identical.

## Routes

| URL             | File                            | Notes                                                                              |
| --------------- | ------------------------------- | ---------------------------------------------------------------------------------- |
| `/`             | `src/routes/index.tsx`          | Navbar, hero, "Today's bakes" grid (array), testimonials, CTA, footer               |
| `/menu`         | `src/routes/menu.tsx`           | Menu sections and prices from `src/lib/menu.ts`, plus its own `head()` meta          |
| `/about`        | `src/routes/about.tsx`          | Static story with several paragraphs, plus its own `head()` meta                     |
| `/__error-test` | `src/routes/[__error-test].tsx` | Dev only. Throws during render. Not linked anywhere                                  |
| (404)           | `src/routes/__root.tsx`         | Template `NotFoundComponent`                                                         |

The shared sections live in `src/components/` (`Navbar`, `Hero`, `TodaysBakes`, `Testimonials`,
`CallToAction`, `Footer`). The copy is the same as in `../lovable-vite`. Most of it is static JSX
text; bakes, testimonials, nav labels, menu items and prices, and the footer year are dynamic.

## Supabase (Lovable Cloud)

This copies Lovable's "enable Cloud" commit from October 2026, made on this same template revision:
[cedricalinc/novalt@951a5e38](https://github.com/cedricalinc/novalt/commit/951a5e3820e8c02f65dc71edd73986a3077e15ff).
The generated files are byte-identical in other projects, for example
[Marcusdrew/rentbnb-buddy@f3ca61cc](https://github.com/Marcusdrew/rentbnb-buddy/commit/f3ca61cca37bdc6e2635c1f419f1cc8acafc5e75).
The commit adds:

- `src/integrations/supabase/`: `client.ts` (lazy `Proxy` that reads `VITE_SUPABASE_*` or
  `process.env.SUPABASE_*`), `client.server.ts`, `auth-middleware.ts`, `auth-attacher.ts`,
  `cron-auth.ts`, `previewAuthStorage.ts` and an empty-schema `types.ts`.
- In `src/start.ts`: `functionMiddleware: [attachSupabaseAuth]`.
- `.env` with `SUPABASE_*` and `VITE_SUPABASE_*`. The values here are placeholders.
- `supabase/config.toml` and an empty `drizzle/` (`schema.ts`, `migrations/meta/_journal.json`).
- In `package.json`: `@supabase/supabase-js`, plus `drizzle-kit`, `drizzle-orm` and `postgres` in
  devDependencies.

The client is built lazily, and no page calls a server function or Supabase, so the app runs
offline. The client bundle still includes `supabase-js` because `start.ts` imports the auth
attacher. That causes the "chunk larger than 500 kB" build warning, which real Lovable Cloud
projects also get.

## Deviations and assumptions

- **Lockfile.** Lovable ships `bun.lock`; this example uses `package-lock.json` from `npm install`,
  as the brief asked. `bunfig.toml` is kept because it is part of the template. npm ignores it.
  Versions are whatever npm resolved on 2026-10-10 within the template's ranges and exact pins.
- **`.gitignore`.** One line, `!.env`, is added at the end. The monorepo's root `.gitignore`
  ignores `.env` files, and Lovable Cloud projects commit theirs.
- **README.** Lovable's README ("Welcome to your Lovable project…") is replaced by this file.
- **`index.tsx` has no `head()`.** This follows the template comment: the home route inherits the
  root meta. `menu` and `about` define their own `head()`, as Lovable apps do.
- **`/__error-test`.** TanStack treats a leading `_` as a pathless layout route, so the file name
  is bracket-escaped (`[__error-test].tsx`). The router generator turns that into the URL
  `/__error-test`. Outside `vite dev`, `beforeLoad` throws `notFound()`. In dev, SSR logs
  `Error in renderToReadableStream`. React then switches that boundary to client rendering and
  returns HTTP 200. On the client the error reaches the root `ErrorComponent` ("This page didn't
  load"), which calls `reportLovableError`.
- **Data location.** The menu data lives in `src/lib/menu.ts`, the convention seen in TanStack-era
  Lovable apps. The classic example uses `src/data/menu.ts`.
- **Design.** Tokens are OKLCH (the template requires it) in `src/styles.css`. They are converted
  from the classic example's HSL palette, so both apps look the same. `@utility` blocks provide
  `container` (centered, 2rem padding), `bg-gradient-*` and `shadow-*`. The app uses no web fonts
  and no remote images.
- **Lint.** `npm run lint` reports Prettier errors in the Lovable-generated
  `src/integrations/supabase/*` files, which are not Prettier-formatted in real projects either, plus
  fast-refresh warnings in `src/components/ui`. The app's own files are Prettier-formatted and lint
  clean. `npx tsc --noEmit` passes.

## Notes for Cloclod tooling

- **Source tagging.** In dev, `@lovable.dev/vite-tanstack-config` registers
  `@tanstack/devtools-vite` with `injectSource: { enabled: true }`. JSX host elements in project
  files then carry `data-tsd-source="/src/components/Hero.tsx:15:11"`, in the SSR HTML too. There
  is no `lovable-tagger` in this template.
- **Sandbox detection.** The config package switches to Lovable's sandbox behavior when
  `LOVABLE_SANDBOX=1` or `DEV_SERVER__PROJECT_PATH` is set. That behavior is `strictPort`,
  `hmr.overlay: false`, the HMR gate and the dev-server bridge. Without those variables it uses
  `host: "::"`, `port: 8080` and file-watch debouncing (`awaitWriteFinish`, 1 s).
- **Build output.** The build writes `.output/` and `.wrangler/deploy/config.json`. The dev server
  writes `.tanstack/`. All three are gitignored by the template.
