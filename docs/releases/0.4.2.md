# Clodable 0.4.2

Released November 21, 2026. Preparing or moving an app now states the intended
result clearly: preserve its appearance, features and data, then check its existing
journeys. This follows the local-app preparation work in
[0.4.1](https://github.com/bworlds-co/clodable/releases/tag/clodable--v0.4.1).

## What builders will notice

- **Clear preservation wording.** The preparation panel and Claude's explanation
  describe adapting the technical setup while preserving the application. They
  explain that an original copy is kept and a feature that cannot be preserved
  must be discussed before proceeding.
- **Before-and-after checks.** Claude records the original journeys and replays
  them after adaptation, including navigation, form validation, persistence after
  reload and server behavior where present. A successful build or recognition by
  Clodable does not prove that these journeys still work.
- **Honest results when resuming.** Rechecking an adaptation still requires its
  journey checks even when Clodable already recognizes the app. Failed or blocked
  comparisons stay explicit; Claude must not declare preparation complete while
  required checks remain unresolved.
- **Explicit choices during a move.** Consent to move off Lovable does not imply
  consent to lose a feature. An optional skipped service must be explained through
  the capability that will stop, and cannot count as a passed check. Existing
  dated rehearsal records remain the evidence for checks on the working copy.

## Updating on another laptop

Update Clodable in Claude Desktop's plugin settings, confirm **0.4.2**, and start a
new Code conversation. To reload an existing conversation, run
`/reload-plugins --force`. Restart any existing preview to load the new runtime.
The command-line equivalent is `claude plugin update clodable@clodable`.

The Desktop plugin includes its CLI. The release attaches
`clodable-plugin-0.4.2.zip`, the matching standalone `clodable-0.4.2.tgz`, and
`SHA256SUMS`. npm registry publication remains pending because this release
environment is not authenticated there; no npm installation is needed for Desktop.

Try preparation on an existing local app. Compare its current pages, forms and
stored data before and after. A request to inspect or verify without making changes
must remain within that scope.

## Verification and limits

All 342 package tests and 227 plugin tests pass, with lint, builds, package type
checks and the plugin type check against generated Claude types. Native Desktop
checks on macOS exercised the original and adapted reservation app, then detected
and repaired deliberately introduced validation and data-retrieval regressions.
A fresh read-only check reported a reintroduced regression without modifying
application sources. The five original files matched the preserved snapshot. No real service was created
or app published by these rehearsals. The
[test record](https://github.com/bworlds-co/clodable/blob/clodable--v0.4.2/docs/testing/PRESERVATION-JOURNEYS.md)
describes the scenarios and evidence.

The change guides Claude's verification; it is not an automatic guarantee that any
application can be migrated without regressions. A full live Lovable move, external
services, clean-laptop OAuth and Windows were not rerun for this patch.
