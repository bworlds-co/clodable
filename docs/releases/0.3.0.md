# Clodable 0.3.0

Clodable now starts with a conversation: describe your idea to Claude, shape the local preview, and set up private saving when you are ready. Existing apps get clearer publishing recovery and a more focused move off Lovable.

## What changed

- **Start from an idea in chat.** No command or duplicate idea field is required. Claude builds the local prototype first; one explicit action creates the private app after account consent. Hosting and shared data remain separate choices.
- **Focused controls.** Your app, History and Settings have their own views. Ordinary requests open the relevant controls, including the current migration step. Setup inspects the app and asks only about uncertain facts; account selection, costs and credentials stay in the panel.
- **Clearer publishing and recovery.** A prepared website is distinguished from a live one. Failed hosting can retry the same saved version without an unrelated edit. Existing sites expose connection recovery, and successful reconnection replaces the form with confirmation and a way back to publishing.
- **A calmer preview.** Preview tools start compact, expand on request and fit short Desktop panes. Conflicting edits are checked without breaking the preview while Claude asks which version to keep.
- **Migration continuity.** Progress requests open the unfinished move, including in retained conversations. Short checkpoints use dated evidence tied to the current copy. Export selection matches the app, supports manually supplied dumps and preserves a usable copy after an unsuccessful replacement. Saved settings remain editable.
- **One installed runtime.** The panel, Claude's app commands and the default preview use the installed plugin's bundled CLI. The plugin also prepares the local tools needed for setup.

## Updating

Update Clodable in Claude Desktop's plugin settings. For an existing command-line installation, run `claude plugin update clodable@clodable`. A marketplace pinned to an older release tag must first be pointed at the new release or the unpinned repository.

Reload plugins in retained conversations, then restart their previews so the conversation and preview use the same release. New conversations load the updated plugin automatically. Your existing app folders and account connections are retained.

The matching standalone command line is `clodable@0.3.0`; `npx clodable@0.3.0 --version` verifies it. The plugin includes its own CLI and does not need a separate npm installation.

## Verification and migration limits

This release includes the fixes verified in the October 17–20 Desktop review: 217 package tests and 155 plugin tests, plus native retained/fresh conversation checks. The review exercised idea-to-publication, everyday editing and recovery, and the Tiny Notes migration copy. Populated local migration tests also checked original passwords and public/private file transfer.

**A complete real migration is still to be tested.** Real email delivery, the AI provider, separate sign-in, hosted behavior and the final live switch remain outstanding. Passing copy checks does not prove those features work. The upcoming rehearsal must verify the app's actual features before changing its live address or finishing in Lovable. See [the owner test guide](../testing/OWNER-TEST-GUIDE.md) and [the UX report](../testing/UX-REPORT.md) for the retained scenarios and evidence limits.

Claude Desktop hides Clodable's above-prompt bar while its native question card is open; this accepted host behavior remains. The separate **Open Clodable** entry provides access to the controls.
