# Clodable 0.4.1

Released November 21, 2026. Existing local apps now get a clear path to preparation and their first private save. This release fixes [issue #121](https://github.com/bworlds-co/clodable/issues/121).

## What builders will notice

- **The right starting point.** An empty folder invites an idea or an import, even when it already has an empty local repository. An app that needs adapting offers **Prepare my app for saving** before a failed save.
- **Plain migration choices.** Claude explains which pages, features and data will stay, then asks whether to adapt the app or keep it as it is. You do not have to choose a framework. A dedicated preparation skill keeps this separate from moving services off Lovable.
- **A preserved original.** Preparation makes and verifies a private local copy before changing the app. Claude checks the application, Clodable support and the working preview before opening saving. The preview blocks access to these private copies.
- **Existing versions stay.** Apps with local versions can be saved after explicit agreement to keep them. Clodable checks earlier versions and current files before sending them. Other projects and existing saving connections are protected.
- **Clear creation and recovery.** Enter the name, continue, then confirm creation in the named GitHub account. A name can be changed while no destination has been reserved. Interrupted setup resumes in the original account. The first saved version appears in History.

Preparation does not create an online service or publish the app. Creating the private app remains a separate action in Clodable's panel.

## Updating on another laptop

Update Clodable in Claude Desktop's plugin settings and confirm **0.4.1**, then start a new Code conversation. In an existing conversation, run `/reload-plugins --force` and reopen Clodable. Restart an existing preview to load the updated runtime.

For a command-line installation, run `claude plugin update clodable@clodable`. If the marketplace is pinned to an older release, use the current marketplace at `https://github.com/bworlds-co/clodable`, then update again.

The Desktop plugin includes its own CLI; no npm installation is needed. The attached `clodable-plugin-0.4.1.zip` contains the plugin, `clodable-0.4.1.tgz` contains the matching standalone CLI, and `SHA256SUMS` records their checksums. npm registry publication remains pending because the release environment is not authenticated there.

Try an existing local app and choose **Set up saving**. If preparation is needed, review Claude's explanation and accept or decline. After successful preparation, choose a name and confirm **Create private app**. For an app with existing local versions, the confirmation explicitly says they will be kept.

## Verification and limits

All 342 package tests and 227 plugin tests pass, along with lint, type checks, builds and catalog coverage. The packaged CLI reports 0.4.1 and matches the plugin bundle; the standalone archive contains the license and dependency notices.

Native Claude Desktop checks on macOS covered empty folders, static-page preparation, accepted and declined server-app adaptation, ordinary edits, name changes and retry, existing local history and the first saved version in History. The final release rehearsal checked the short French consent, the dedicated skill, verified originals, a preserved reservation route and the working preview. The detailed source test records are [issue #121](https://github.com/bworlds-co/clodable/blob/clodable--v0.4.1/docs/testing/ISSUE-121.md) and [preparation routing](https://github.com/bworlds-co/clodable/blob/clodable--v0.4.1/docs/testing/PREPARATION-SKILL.md).

Saving tests used a local stand-in for GitHub and real secret scanning. They did not create real GitHub resources or repeat OAuth on a clean laptop. Windows first-run behavior and a full live move off Lovable were not retested. The other laptop remains the check for its real account, network and installation environment.
